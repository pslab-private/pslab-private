# 글 작성 안내

## 가장 빠르게 시작하기

```sh
pnpm new-post debugging-a-timeout "타임아웃의 원인을 찾는 과정"
pnpm dev
```

`src/content/posts/debugging-a-timeout.md`를 편집하고 http://localhost:4321/psl-tech/posts/debugging-a-timeout/ 에서 확인합니다. 초안은 개발 모드에서만 표시됩니다.

## 글의 기본 정보

```yaml
---
title: "타임아웃의 원인을 찾는 과정"
description: "어떤 환경에서 발생한 문제를 어떻게 해결했는지 소개합니다."
pubDatetime: 2026-11-09T10:00:00+09:00
tags: ["네트워크", "문제 해결"]
featured: false
draft: true
---
```

| 필드          | 작성 규칙                                                                 |
| ------------- | ------------------------------------------------------------------------- |
| `title`       | 제목. 따옴표로 감싸면 콜론 등을 안전하게 입력할 수 있습니다.              |
| `description` | 글 목록·검색·공유용 요약. 필수 항목입니다.                                |
| `pubDatetime` | 발행 날짜와 시간. 한국 시간은 `+09:00`을 붙입니다.                        |
| `modDatetime` | 발행 후 내용을 고쳤을 때 추가하는 수정일입니다.                           |
| `tags`        | 2~4개 정도의 일관된 태그를 권합니다. 한글도 가능합니다.                   |
| `featured`    | `true`인 글 중 가장 최근 글을 홈의 추천 글로 보여줍니다.                  |
| `draft`       | `true`면 배포 결과, 검색, RSS에서 제외합니다. 발행 시 `false`로 바꿉니다. |
| `author`      | 선택 항목. 생략하면 사이트의 기본 작성자를 사용합니다.                    |
| `hideToc`     | `true`면 해당 글의 목차를 숨깁니다.                                       |

**공개 저장소의 초안 원문도 공개됩니다.** `draft`는 사이트 표시 여부만 제어합니다.

미래 날짜의 글은 해당 날짜 이전의 배포 빌드에서 제외됩니다. 날짜만 설정한다고 자동 발행되지 않습니다. 발행일에 수동으로 빌드를 실행하거나 `main`에 변경을 반영하세요. 기본 워크플로에는 예약 실행을 넣지 않았습니다.

## 본문 작성

제목은 자동으로 표시되므로 본문은 `##`부터 시작합니다. `##`, `###` 제목은 자동으로 목차에 표시됩니다.

````markdown
## 문제 상황

문단 사이에는 빈 줄을 둡니다. **강조할 내용**과 `짧은 코드`를 쓸 수 있습니다.

### 재현 코드

```ts file="example.ts"
const message = "안녕하세요";
console.log(message);
```

> [!NOTE]
> 본문 흐름에서 분리할 보충 설명입니다.

- 첫 번째 항목
- 두 번째 항목

| 방법    | 결과        |
| ------- | ----------- |
| 변경 전 | 관찰한 결과 |
| 변경 후 | 검증한 결과 |
````

일반적인 글은 `.md`를 쓰면 충분합니다. 컴포넌트를 직접 넣어야 하는 글에서만 `.mdx`를 사용하세요. Mermaid와 수식 렌더링은 별도 설정이 필요하며 현재 기본 구성에는 포함하지 않았습니다.

## 이미지 추가

글에 사용할 이미지를 `src/assets/images/글-주소/` 아래에 넣는 것을 권합니다. 이 위치의 이미지는 Astro가 최적화합니다.

```markdown
![실행 결과를 비교한 화면](../../assets/images/my-first-note/result.png)
```

위 경로는 `src/content/posts/my-first-note.md` 기준입니다. 하위 폴더에 글을 넣으면 상대 경로도 함께 조정하세요. 이미지 설명에는 무엇을 보여주는지 적습니다.

`public/`의 이미지는 최적화 없이 그대로 배포됩니다. `/psl-tech/` 하위 경로가 있으므로 본문에서 `/images/...` 같은 루트 절대 경로를 사용하면 주소가 깨질 수 있습니다. 글별 공유 이미지는 한글 제목과 요약으로 자동 생성되므로 대표 이미지를 매번 만들 필요가 없습니다.

## VS Code에서 버튼과 입력란으로 관리하기

1. 권장 확장 프로그램 **Front Matter CMS**를 설치합니다.
2. 이 저장소 폴더를 열고 Front Matter 대시보드를 엽니다.
3. 저장소에 포함된 `frontmatter.json`을 그대로 사용합니다. 재초기화할 필요는 없습니다.
4. 글 목록과 제목·요약·발행일·태그·초안 항목을 편집합니다.
5. 터미널에서 `pnpm dev`를 실행한 상태로 미리 봅니다.

새 파일 생성은 위의 `pnpm new-post` 명령을 권합니다. 편집기에서 저장만 하면 로컬에 반영되며, 웹에 게시하려면 Git 커밋과 push가 필요합니다. 발행 직전에 초안을 해제하고 날짜를 확인하세요.

## GitHub에서 간단히 수정하기

저장소의 Markdown 파일을 열고 연필 버튼으로 수정하거나, 저장소 화면에서 `.`을 눌러 github.dev 편집기를 엽니다. 커밋을 `main`에 반영하면 자동 배포됩니다. 웹 편집기의 Markdown 미리보기는 블로그 디자인 전체를 재현하지 않으므로 큰 변경은 로컬에서 확인하세요.

## 글의 주소 관리

파일명은 글 주소가 됩니다. 발행한 글의 파일명이나 폴더를 바꾸면 기존 링크도 바뀌므로 가능한 유지하세요.

```text
src/content/posts/my-note.md           → /psl-tech/posts/my-note/
src/content/posts/web/my-note.md       → /psl-tech/posts/web/my-note/
src/content/posts/_2026/my-note.md     → /psl-tech/posts/my-note/
```

같은 최종 주소를 가진 파일을 두 개 만들지 않도록 주의하세요. 관리 편의를 위해 처음에는 글을 `src/content/posts/`에 평평하게 두고 태그로 분류하는 것을 권합니다.

## 발행 전 확인

- 제목·요약·태그와 발행 날짜가 올바른지 확인합니다.
- 코드, 이미지, 표를 모바일 화면에서도 확인합니다.
- 개인정보와 내부 주소, 비밀 키가 없는지 살펴봅니다.
- `draft: false`로 바꾸고 `pnpm test`, `pnpm build`, `pnpm verify`를 실행합니다.
- GitHub에 반영한 뒤 Actions의 배포 성공 여부를 확인합니다.
