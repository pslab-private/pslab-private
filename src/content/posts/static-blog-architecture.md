기술 블로그의 핵심은 글을 저장하고 독자에게 빠르게 전달하는 것입니다. 모든 방문마다 서버에서 같은 문서를 새로 만들 필요가 있을까요?

## 문서는 미리 만들 수 있습니다

정적 사이트는 작성한 글과 화면 템플릿을 빌드 과정에서 HTML로 변환합니다. 독자가 방문하면 이미 만들어진 파일을 전달합니다.

```text
Markdown 글 + 화면 템플릿
          ↓ 빌드
HTML + CSS + JavaScript + 이미지
          ↓ 배포
      GitHub Pages
          ↓
        독자
```

읽는 시점에 데이터베이스를 조회하거나 서버에서 템플릿을 실행하지 않아도 됩니다. 이 블로그 역시 Astro가 글을 웹 문서로 만들고 GitHub Pages가 그 결과를 제공합니다.

## 글 한 편은 하나의 파일

본문과 제목, 요약, 태그는 같은 Markdown 파일에 보관합니다. 파일의 변경 이력이 Git에 남기 때문에 잘못 수정한 내용을 되돌리거나 변경 이유를 확인할 수 있습니다.

```yaml
title: "하나의 질문을 해결한 기록"
description: "문제와 해결 방법을 한 문장으로 소개합니다."
tags: ["개발", "문제 해결"]
```

화면의 디자인을 바꾸더라도 글 자체는 텍스트 파일로 유지됩니다. 다른 도구로 옮길 때도 본문을 다시 입력할 필요가 없습니다.

## 검색은 어떻게 동작할까요?

정적 사이트라고 검색이 불가능한 것은 아닙니다. 이 블로그에서는 빌드가 끝난 HTML을 Pagefind가 읽어 검색 색인을 만듭니다. 방문자의 브라우저는 필요한 검색 파일을 내려받아 결과를 보여줍니다.

별도 검색 서버를 운영하지 않아도 되지만, 새 글과 수정 내용이 검색 결과에 반영되려면 **사이트를 다시 빌드해 배포해야 합니다.**

## 적합한 범위 이해하기

| 정적 사이트에 잘 맞는 기능 | 추가 서비스가 필요한 기능           |
| -------------------------- | ----------------------------------- |
| 글 목록과 상세 페이지      | 로그인 기반 개인화                  |
| 태그와 목차                | 비공개 회원 전용 콘텐츠             |
| RSS와 사이트맵             | 데이터베이스에 저장하는 실시간 기능 |
| 빌드 시 생성한 검색 색인   | 서버에서 처리하는 폼과 인증         |

요구 사항이 글을 읽고 탐색하는 데 집중되어 있다면 정적 사이트는 관리할 부분을 줄여줍니다. 이후 동적인 기능이 필요해졌을 때 해당 기능에 맞는 서비스를 연결할 수 있습니다.
